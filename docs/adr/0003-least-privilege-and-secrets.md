# 3. Least privilege and no secrets in the repository

Status: accepted (2026-10-07)

## Context

The services only read data, the stack runs on developer machines, and the
repository is shared. Credentials leak most often through committed config,
project files and shell history.

## Decision

- Two roles: `fibre_owner` (migrations, loads) and `fibre_reader` (`SELECT`
  only). The API, GeoServer and QGIS use the reader. API sessions are also
  `default_transaction_read_only` with a 10 s statement timeout.
- All passwords come from `.env` (git-ignored, random values generated by
  `run.ps1 setup`); `.env.example` holds placeholders. A pre-commit hook
  blocks committing `.env` files and private keys.
- The QGIS project connects with `service=fibre`; the password lives in the
  user's `pg_service.conf`, which `setup_pg_service.ps1` restricts to that
  user.
- Every port is published on 127.0.0.1 only. Package uploads need a password;
  published versions are immutable.
- API input is validated (LAD code pattern, bbox size, result limits, postcode
  format) and all SQL is parameterised; identifiers that must be inlined
  (role names in migrations) are checked against a strict pattern.
- The data is aggregated statistics (people per address modelled from census
  totals, coverage per postcode), with no personal data.

## Consequences

- A bug or a compromised service cannot change data (tested:
  `test_reader_role_cannot_write`).
- New developers run `run.ps1 setup` and get working, unique credentials.
